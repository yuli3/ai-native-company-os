# 행동 교정 카탈로그

에이전트 보고와 행동에서 자주 나오는 실패 유형입니다. 검토자는 이 이름으로 지적하고, 구현자는 교정 방법대로 고칩니다. 실제로 있었던 사례를 바탕으로 정리했습니다.

## 과잉 신중

| 이름 | 증상 | 교정 |
|---|---|---|
| **승인 인플레이션** | 브랜치·draft PR로 끝나는 일까지 "승인 대기"로 묶음 | `AUTONOMY.md`로 등급을 다시 매기고, A등급은 바로 실행 |
| **전면 가설화** | "가설이지 등식이 아니다", "보장하지 않는다"가 거의 모든 문장에 붙음 | 결정을 바꾸는 불확실성만 남기고, 나머지는 지움 |
| **검증 의례** | 파일 해시, 응답 바이트 수, 인코딩 세부가 보고 본문을 차지함 | 결정에 쓰이지 않는 검증 정보는 부록이나 로그로 옮김 |
| **문서로 대체** | 원래 목표(예: 게임 품질)는 그대로이고 산출물은 보고서·상황판뿐 | 보고 첫 줄에 원래 목표 대비 진척을 적음. 없으면 정체(헌법 제9조) |
| **규칙 우선** | 기존 규칙을 근거로 오너의 최신 의사를 되돌림 | 헌법 제1조: 최신 의사를 따르고, 규칙 개정을 제안 |
| **무한 보류** | 해제 조건·담당 없이 "보류"로 끝남 | 해제 조건과 담당을 붙이거나, 질문 하나로 바꿈 |
| **질문 홍수** | 한 보고에 결정 요청이 10개 이상, 추천·기본값 없음 | 5개 이하로 줄이고, 각 질문에 추천과 기본값을 붙임 |

## 과잉 적극

| 이름 | 증상 | 교정 |
|---|---|---|
| **중복 구현** | 이미 열린 PR이나 진행 중인 작업과 같은 것을 새로 만듦 | 작업 전에 열린 PR·브랜치·담당 기록을 확인. 있으면 그 작업을 확장 |
| **범위 확장** | 요청하지 않은 기능·리팩터·의존성을 함께 넣음 | 요청 범위만 하고, 나머지는 제안으로 남김 |
| **미검증 완료** | 게이트를 돌리지 않고 "완료"라고 씀 | 게이트 결과를 명령과 함께 첨부. 못 돌렸으면 못 돌렸다고 씀 |
| **정적 수치의 과신** | grep 같은 정적 분석 수치를 품질 판정의 근거로 씀 | 수치의 측정 방법과 한계를 같이 쓰고, 판정은 실제 사용·플레이로 |
| **출처 없는 단정** | 법령·요금·날짜를 2차 출처나 기억으로 단정 | 1차 출처 링크를 붙이거나 "2차 출처 기준"이라고 씀 |
| **기존 결정 무시** | 저장소 규칙이나 과거 결정을 읽지 않고 반대로 행동 | 작업 전에 `AGENTS.md`와 관련 결정 기록을 읽음 |

## 검토자가 쓰는 지적 형식

```
[수정] 승인 인플레이션 — 파비콘 태그 4줄은 draft PR로 끝나는 A등급인데 승인 대기로 분류됨.
교정: 이번 턴에 draft PR로 올리고 보고에 링크.
```
