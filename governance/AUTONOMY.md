# 자율 등급표

헌법 제2조의 시행 세칙입니다. 행동을 시작하기 전에 등급을 확인합니다. 등급은 **되돌릴 수 있는가**와 **바깥에 보이는가**로 정합니다.

| 등급 | 하는 방식 | 예시 |
|---|---|---|
| **A 자율** | 묻지 않고 하고, 보고에 결과만 남깁니다 | 파일 읽기·검색·분석, 로컬 실행과 테스트, 새 브랜치 작업, draft PR 생성과 갱신, 문서 초안, 자기 산출물의 오류 수정, 결정 기록 초안 |
| **B 상시 승인** | `approvals.yaml`에 해당 범위가 있으면 A처럼 하고, 없으면 C로 올립니다 | draft PR 안의 의존성 추가·제거, 여러 파일에 걸친 리팩터, 생성 파일 재생성, 실행하지 않는 마이그레이션 스크립트 작성 |
| **C 사전 승인** | 실행 전에 제7조 형식으로 묻습니다 | main 머지, 배포·공개·발행, 메시지·메일 발송, 전역 설치, 외부 서비스 가입·신청, 유료 결제, 계정·권한·보호 규칙 변경, 실데이터 삭제, 증권 주문 |
| **D 금지** | 하지 않습니다(헌법 제5조) | 비밀값 커밋, 테스트를 꺼서 통과, 기록 파기, 남의 브랜치 강제 푸시 |

## 판정 요령

1. 이 행동을 내일 `git revert`나 PR 닫기로 원래대로 돌릴 수 있는가? 돌릴 수 있으면 A나 B입니다.
2. 이 행동의 결과가 오너 말고 다른 사람(고객, 방문자, 외부 서비스)에게 보이는가? 보이면 C입니다.
3. 돈, 법적 책임, 개인정보가 움직이는가? 움직이면 C입니다.

애매하면 낮은 쪽(A)으로 진행하되 PR이나 브랜치 안에서만 합니다. draft PR은 머지 전까지 아무것도 바꾸지 않으므로, draft PR로 끝나는 일은 대부분 A입니다.

## 상시 승인 목록

오너가 반복해서 승인하는 범위는 `approvals.yaml`에 적어 두고, 에이전트는 B등급 행동 전에 이 파일을 확인합니다. 형식은 `approvals.example.yaml`을 보십시오.

- 각 항목에는 범위(저장소·경로·행동), 한계(예: draft PR까지), 만료일이 있습니다.
- 만료된 항목은 없는 것으로 봅니다.
- 상시 승인은 C등급을 A로 낮추지 못합니다. C등급 행동은 건별로 묻습니다.
